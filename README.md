# FoldQuest for Nintendo 3DS

**WIP software candidate (T1 first slice). Built for the 3DS toolchain; NOT device-tested, NOT a release.**

One original room, two folds. Walk the yellow tile to `G`. Some gates are closed in fold A and open in fold B (and vice versa); the room folds **once each time the console actually suspends and resumes** (close the lid, or press HOME and return). A complete solve needs two real folds.

Part of [lafiabrew](https://github.com/lafiabrew). UniqueId `0x0D3F7`, ProductCode `CTR-P-FOLD`.

## Controls
D-pad / Circle Pad or tap an adjacent tile: move. `Y` or PRACTICE button: practice fold (a rehearsal; counted separately, not a real resume). `SELECT` or RESET: reset the room (resume counters are kept). `X` or EXPORT: explicit diagnostic export. `START`: quit.

## Lifecycle behavior (what is real)
- Native builds register a real libctru `aptHook`. `ONSLEEP`/`ONWAKEUP` (lid) and `ONSUSPEND`/`ONRESTORE` (HOME) only enqueue an event; the main loop then applies it. No work, timers or simulation happen while suspended; time spent suspended is not counted.
- The core flips the fold exactly once per resume; a resume without a suspend is ignored and counted.
- Game state lives **in RAM only**. It survives normal sleep/HOME, and is lost on quit, power loss, or battery death. There is no saved campaign.
- Original 3DS is the baseline (no New 3DS-only features are used; `new3ds_enhancements` is exported as `false`). Rendering is 2D (stereoscopic 3D is off).
- The host build (`build/host/3ds_foldquest_host`) is a **simulation** with scripted input and simulated lifecycle events; it is not hardware and not APT.

## Diagnostics (not save data)
`X` writes JSON Lines to `sdmc:/3ds/logs/3ds_foldquest.log` (host: `<sd-root>/3ds/logs/...`) through the vendored lafiabrew journal (`vendor/lafiabrew_journal`, hashes in `PROVENANCE.json`, unchanged). Each record has `schema, app, build, event, elapsed_us, seed, settings, capabilities`; `seed` is the room id (`1`), `elapsed_us` is awake play time, the first record is `log_open` (<=199 ASCII bytes), the active file is <=256 KiB and rotates once to `3ds_foldquest.previous`. Capabilities report a coarse model (`o3ds`/`n3ds` from `APT_CheckNew3DS`, null when unknown), touch and APT-hook presence. No paths, identities or addresses are logged. The log is never read back to restore a game. Corrupt, torn or foreign log bytes are refused and retained (never trimmed); an interrupted export is rolled forward by the next export or by quit. Collect it with the existing 3ds_drop `/api/logs` and `/api/pull?path=3ds/logs/3ds_foldquest.log`; FoldQuest runs no server.

## Build status and source license
`make test` runs ASan/UBSan C tests (core, app, log, APT-hook adapter against a declaration shim) plus the shared `journal-check` regression (which is not app acceptance). `make 3ds` builds ELF/SMDH/3DSX/CIA/CXI in the toolchain container (or natively when `DEVKITARM` is set); `make verify-3ds` checks symbols, main() call-graph reachability, SMDH/CIA/CXI metadata and rejects a same-ARM stub launcher and a call-edge mutant. It inspects the actual CIA content and standalone CXI: ExeFS must contain only `.code` and the verified SMDH `icon`, with no `banner`/`logo` entries and no NCCH logo region. Production-CIA mutation controls exercise these checks; title/product identity, unencrypted content flags and the original icon remain checked.

### Packaging provenance boundary
Only the original procedural clamshell icon is generated by `meta/generate_assets.py`: arithmetic panels, crease and border, with no imported image/model/audio. Its existing pixel algorithm and SMDH metadata settings are retained and regression-pinned. The optional HOME-menu 3D banner/chime and boot logo are intentionally **omitted**, not replaced. The inherited banner encoder and its opaque CGFX template have been removed; `meta/app.rsf` uses `Logo: None` and makerom receives no banner/logo import options. The installed makerom 0.18.4 source (`Project_CTR` pin `c0488dcb6c3048e6a519716f2b21e2c65859ca75`, `ImportLogo` and ExeFS imports) supports this omission. No game code or journal bytes change.

This is native compilation and structural artifact proof only. Installation, HOME-menu presentation without a banner, boot behavior, rendering and physical lid/HOME operation remain **unverified on device**. Prior provenance failures are retained in the coordinator's reports; omission is not a retroactive clearance of those assets.

New original code/runtime scaffold is MIT. Hardware behavior (real lid sleep on a console) is unverified until an owner-console run.
